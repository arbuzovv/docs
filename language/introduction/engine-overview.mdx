Ziplime is an open-source Python backtesting engine: [github.com/Limex-com/ziplime](https://github.com/Limex-com/ziplime). This section documents the engine as you install and run it yourself — current version **2.11.0**.

Ziplime started as a fork of **Zipline**, the engine behind Quantopian, and keeps its programming model: `initialize`, `handle_data`, `context`, `data`, `order_target_percent`. Most of the engine underneath has since been rewritten: Polars instead of pandas in the data layer, asyncio end to end, and Python 3.12+.

<Note>
  The hosted platform at [ziplime.limex.com](https://ziplime.limex.com) runs the same engine inside a sandbox with a narrower contract: no imports, only `initialize` and `handle_data`, no config class. This section describes the open-source engine. On the hosted platform, follow the rules its own editor and MCP server give you.
</Note>

## Strict by default

The engine is built to catch what a hand-written or AI-written strategy gets wrong. The shortcuts that make a backtest look better have to be asked for by name:

- **Next-bar fills.** In the CLI and the local MCP server an order fills on the bar after the decision. Same-bar fills are an explicit flag.
- **Look-ahead checks on vectorized signals.** `compute_signals` is recomputed on truncated history, and a signal that used the future stops the run before the first order.
- **Point-in-time data.** Datasets such as fundamentals or insider trades are windowed by the date a row became public, not by the period it describes.
- **Costs are applied or refused, never dropped.** A cost model that can't be applied stops the run by name.
- **No tool places an order on its own.** The local MCP server has no order tool.

## What's in the box

| Area | What you get |
| --- | --- |
| Asset classes | Equities and ETFs, futures, options, bonds — in one portfolio, one cash balance, one ledger |
| Simulation | Event-driven engine plus a vectorized kernel, both reporting through the same ledger and cost models |
| Bar sizes | Any emission rate from one minute to one day (5 minutes, 15, an hour…) |
| Data | Yahoo Finance, CSV, LimexHub, point-in-time datasets on the Hugging Face Hub, extension data sources |
| Venues | Each listing keeps its own venue's trading hours, so one run can mix markets |
| Running | Command line (`ziplime …`), Python API (`run_simulation`), local MCP server for AI agents |
| Live | The same strategy file runs live on Lime through the Lime Trader SDK |
